# RAG 적용 전/후 판결 비교

법령·판례 검색(RAG)을 붙인 판결이 그 전과 무엇이 달라졌는지, 실제 Gemini로 사연 10개를 돌려 비교했습니다. 평가일: 2026-11-11. 스크립트: [`scripts/rag-eval.mjs`](../scripts/rag-eval.mjs) (`npm run eval:rag`).

## 결론 요약

| 항목                                 | A. RAG 전 (기존 코드) | B. RAG 후                               | C. 검색 없이 "법을 인용하라"고만 지시                  |
| ------------------------------------ | --------------------- | --------------------------------------- | ------------------------------------------------------ |
| 법률 사연 7건 중 법적 근거 인용      | **0건**               | **7건**, 모두 사연에 맞는 근거          | 7건                                                    |
| 무관한 사연 3건에서 "근거 없음"      | (인용 자체 없음)      | **2건** (1건은 일반 조문을 단서와 인용) | 0건, 3건 모두 조문·판례 인용                           |
| 존재하지 않는 판례 번호              | 0                     | **0**                                   | **판례 9건 중 5건** (공개 DB에 없음 4, "2010다○○○○" 1) |

| 사연에 맞지 않는 조문                | 0                     | 0                                       | 3건 (권리능력 제3조 등)                                |
| 인용 검증에 걸려 재시도              | –                     | 0회                                     | –                                                      |
| 판결 응답 시간 (중앙값)              | 5.5초                 | 7.0초 (그중 검색 0.5~0.7초)             | 6.1초                                                  |
| 판결 1회 입력 / 출력 토큰 (평균)     | 2,233 / 372           | 3,125 / 417                             | 2,132 / 224                                            |
| 판결 1회 비용 (유료 단가 환산, 평균) | $0.00160              | $0.00198 (+24%)                         | $0.00120                                               |

- **RAG 전(A)에는 지어낸 법도 없었지만 법적 근거도 없었습니다.** 사용자가 "법적으로는 누구 책임인지 알려 주세요"라고 해도, 기존 프롬프트("확인된 사실과 출처를 밝힌 진술만 근거로")를 따라 조문을 쓰지 않았습니다.
- **법적 근거를 "프롬프트로만" 요구하면(C) 그럴듯한 환각이 바로 나옵니다.** 조문 번호는 실재했지만, 판례 9건 중 사연에 맞는 실재 판례는 1~2건뿐이었습니다. 출처 표시 형식("대법원 2014. 5. 16. 선고 2012다49933 판결")이 정확해 보여 사용자가 의심하기 어렵습니다.
- **RAG(B)는 근거를 붙이면서 환각을 0으로 유지했습니다.** 인용은 검색된 id만 고를 수 있게 스키마로 막았고, 인용 근거 밖의 조문·사건번호는 검증에서 거절하게 했습니다(이번 평가에서 거절된 응답은 0건). 대가는 판결 1회당 입력 약 900토큰(+40%), 비용 +24%, 검색 0.5~0.7초입니다.

## 평가 방법

### 세 가지 조건

같은 재판 상태를 세 조건에 똑같이 넣었습니다. 사연마다 opening(첫 심리)을 현재 코드로 한 번 진행하고 심문을 종료해, 원고 진술이 동일한 closing 상태를 만든 뒤 판결만 세 번 받았습니다. 순서는 사연마다 돌렸습니다(A→B→C, B→C→A, C→A→B).

- **A. RAG 전**: RAG 직전 커밋 `edfbdbf`의 서버 코드를 별도 worktree에 빌드해 그대로 호출. 프롬프트·스키마·검증이 모두 당시 그대로입니다. 현재 코드에서 `RAG_MODE=off`로 끄는 방식은 쓰지 않았습니다. 지금 프롬프트에는 이미 "근거가 없으면 조문을 쓰지 마라"는 규칙이 있어서 진짜 "전"이 아니기 때문입니다.
- **B. RAG 후**: 현재 코드. 판결 직전에 검색(gemini-embedding-2, 코사인 유사도, top-3, 임계값 0.65)하고 근거를 프롬프트에 넣습니다.
- **C. 프롬프트로만 법적 근거 요구 (스트레스 테스트)**: A의 시스템 프롬프트에 "판결 이유에 한국 법령 조문(법령명과 조 번호)과 대법원 판례(사건번호)를 근거로 인용하라"를 한 줄 덧붙이고, 검색은 하지 않습니다. 실제 서비스 조건이 아니라, RAG 없이 "법적 근거"를 붙이려 할 때의 위험을 보기 위한 대조군입니다.

모델은 세 조건 모두 `gemini-3.5-flash-lite`(thinking low, temperature 0.35)입니다. 기본 모델이 503/504를 내면 서비스 로직대로 `gemini-3.8-flash`로 재시도하고, 그래도 실패하면 평가 스크립트가 20초 뒤 한 번 더 시도했습니다.

### 판정 기준

- **법 조문·판례 추출**: 판결의 제목·결과·이유·미확인 정보·화해 권고·한마디·근거 설명에서 `제N조(의M)`와 사건번호(`99다34697` 형식)를 정규식으로 뽑았습니다. 서버의 인용 검증과 같은 함수([`shared/legal-refs.ts`](../shared/legal-refs.ts))입니다.
- **조문 실재 여부**: 법령 원문 파일(legalize-kr, 고정 커밋)의 조 제목과 대조했습니다.
- **판례 실재 여부**: 판례 저장소의 민사 대법원 판례 파일 목록 전체(28,834건, 잘림 없음)와 사건번호를 대조했습니다. 목록에 있는 판례는 판시사항을 읽어 사연과 맞는지 판단했습니다. 공개 판례 DB에 모든 판결이 있는 것은 아니므로 "목록에 없음"은 "지어냈을 가능성이 높음"으로 해석했습니다.
- **근거가 사연에 맞는지**: 판결 문장을 직접 읽고 판단했습니다(사람 판정).
- **토큰·비용**: 응답의 `usageMetadata`(출력에는 thinking 토큰 포함)를 두 빌드에서 같은 방식으로 기록했습니다. 비용은 유료 단가(입력 $0.30, 출력 $2.50 / 100만 토큰, 임베딩 $0.20 / 100만 토큰)로 환산했습니다. 이번 평가 자체는 무료 등급이라 실제 비용은 0원입니다. 임베딩 API는 사용량을 돌려주지 않아, 질의 상한 1,500자를 토큰으로 잡았습니다(판결당 약 $0.0003 이하).

## 임계값 0.65에 대해

| 사연 분류       | 검색 1위 유사도 |
| --------------- | --------------- |
| 법률 사연 7건   | 0.717 ~ 0.784   |
| 무관한 사연 3건 | 0.61 ~ 0.709    |

사전 점검(사연 8개)에서는 두 분류가 0.65를 사이에 두고 갈렸지만, 이번 평가에서는 무관한 사연 2건(chicken .696, dishes .709)이 임계값을 넘었습니다. opening에서 모델이 쓴 검색어가 "재산 손해 배상 청구", "민사 채무불이행"처럼 법률 용어로 바뀌면서 점수가 올라간 것으로 보입니다. **이번 평가에서 무관한 근거를 걸러낸 것은 임계값보다 LLM 쪽이었습니다**("맞지 않는 자료는 인용하지 마라" 규칙). dishes는 걸러졌고, chicken은 일반 조문을 단서와 함께 인용했습니다. 임계값을 0.72로 올리면 이번 10건은 깔끔하게 나뉘지만, 표본이 작아 법률 사연의 2·3순위 근거도 함께 잘려 나갑니다. 그래서 0.65를 유지하고 한계로 기록합니다.

## 한계

- **표본이 작습니다.** 사연 10개, 조건별 1회씩입니다. 같은 사연을 다시 돌리면 결과가 달라질 수 있습니다. 첫 실행(A/B만, 동일 사연)과 비교하면 법률 사연 6건 중 5건이 같은 근거를 인용했고, noise는 다른 근거(2014다57846 → 공동주택관리법 제20조)를 골랐습니다. chicken은 첫 실행에서 "근거 없음"이었다가 이번에는 민법 제750조를 인용했습니다.
- **과부하 재실행**: 처음 실행에서 Gemini 503/504 때문에 opening 또는 B가 실패한 4개 사연(noise, deposit, camera, dishes)은 같은 스크립트로 다시 돌린 결과로 대체했습니다. 첫 실행의 C에서도 같은 유형의 오류가 나왔습니다. 카메라 사연에 고용 조문(민법 657조)과 의료과실 판례(93다59304), 층간소음 사연에 공작물 책임(758조)이 인용됐습니다.
- **B는 근거를 소극적으로 씁니다.** "조문은 가볍게 참고하라"는 오락용 규칙 때문에, 근거를 인용하고도 결론은 "판단 유보"인 경우가 많았습니다. 예를 들어 used-bike에서 제565조를 인용했지만 "배액을 상환해야 해제할 수 있다"는 내용을 결론에 적용하지 않았습니다. 판결 결과 자체의 품질은 이번 평가 범위 밖입니다.
- **검증은 "형식"까지만 봅니다.** 인용 근거 밖의 조 번호·사건번호는 막지만, 인용한 근거를 왜곡해 설명하는 것은 프로그램으로 판정하지 않습니다. 이번 B의 근거 설명 10건은 사람이 읽어 확인했습니다.
- **판례 실재 확인은 공개 DB 기준입니다.** 공개되지 않은 판결일 가능성을 완전히 배제하지는 못합니다. 다만 C가 인용한 "공개 DB에 없는" 번호 4건은 모두 사연 주제와 맞는 공개 판례도 따로 있는 분야였습니다.
- **비용은 단가 환산입니다.** 유료 단가는 Google 가격 페이지를 인용한 제3자 자료로 확인했습니다(2026-11-11). 실제 청구 금액은 등급과 시점에 따라 다를 수 있습니다.
